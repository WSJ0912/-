# 安全设计

## 保护目标

保护原始影像路径、受控标识、本地数据库、模型完整性、OpenAI 密钥和医生确认权限。威胁模型包括错误或恶意导入文件、篡改的模型/实验 ZIP、渲染进程受损以及本机其他进程探测服务端口；不声称抵御已取得当前 Windows 用户或管理员权限的攻击者。

## Electron 边界

- `nodeIntegration=false`、`contextIsolation=true`、sandbox 开启。
- CSP 禁止外部脚本、对象和框架；新窗口及非当前页面导航被拒绝。
- preload API 冻结，只暴露固定命令和受限服务请求。
- 通用 `service:request` 只接受方法与正则路径双重白名单。
- 需要本地路径的暂存、模型安装、实验导入和 PDF 导出由主进程文件对话框完成；渲染进程只得到选择句柄或结果，不得到路径。
- 服务进程令牌永不传给渲染进程；登录响应中的会话令牌由主进程截留。
- 助手密钥写入由主进程再次校验管理员角色，不能只依赖隐藏按钮。

## 本地服务与身份

- 服务仅绑定 `127.0.0.1` 随机端口，每次启动生成至少 32 字节随机进程令牌。
- 所有接口都要求进程令牌；业务接口另要求内存会话令牌。
- 退出登录撤销服务端会话并清理主进程中的令牌、角色和临时选择句柄。
- 密码至少 12 位，只存 Argon2id 哈希。
- 管理员可管理用户、模型和助手设置，但没有推理、复核、报告或确认权限。
- 医生可推理、复核和确认本人报告，但不能安装模型、创建账号或修改助手设置。

## 文件与模型

- 导入文件先复制到隔离临时区，按解码结果而非扩展名判断准入。
- DICOM 去标识化、UID 替换、烧录文字遮挡和 raster 重编码见 `DATA_GOVERNANCE.md`。
- `.medmodel` 和 `.medexperiment` 拒绝绝对路径、`..`、反斜杠路径、重复条目及意外文件。
- 模型清单固定 14 项标签、320 x 320 输入、阈值、来源、许可和每个文件 SHA-256。
- 模型在激活前先从临时包创建真实 ONNX Runtime 会话；加载失败不会替换当前可用模型。
- 服务重启时依据指针中的模型和清单哈希重新验证，不能通过简单替换文件恢复激活。

## 在线助手

- API 密钥使用 Electron `safeStorage` 加密后写入用户数据目录，不进入 Git、日志或服务数据库。
- 请求固定使用 Responses API、`store:false`、空工具列表和严格 JSON Schema 输出。
- 发送前递归拒绝路径、影像、DICOM、患者/检查/用户/报告等受控标识字段。
- 仅允许聚合实验指标，或去标识化观察、医生复核和医生输入文字。
- 自由文本无法可靠自动识别全部隐私内容；操作者仍必须避免在医生文字中输入身份信息。
- 无密钥、断网、超时或结构化响应失败时返回明确的离线模板提示，不伪装成在线生成结果。

## 发布要求

- 不提交 `.env`、数据库、日志、影像、权重、研究运行目录或 `*.local.json`。
- 发布前运行依赖许可清单生成器和 `npm audit`，检查安装包内 `resources/legal`。
- 正式安装包应代码签名；v0.1 当前构建流程尚未配置证书。
- 安全机制不能把本项目转化为合规医疗器械。部署到临床环境前需要独立威胁建模、隐私影响评估、机构审批和法规流程。
