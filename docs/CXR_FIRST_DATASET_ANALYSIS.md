# CXR First 数据画像与精度提升路线

本文件基于本机全量数据（不是抽样）统计，数据目录 `cxr_first/cxr_first`（51.6 GB，33,987 个文件），
标签映射来自主办方官方类别表。所有数字可用 `python -m cxr_competition stats` 复现。

## 一、数据规模与划分

| 划分 | 图像 | 检查 Study | 患者 Subject | 患者 ID 范围 | Study ID 范围 |
| --- | ---: | ---: | ---: | --- | --- |
| train | 30,344 | 18,513 | 11,055 | 0–11812 | 0–19999 |
| valid | 1,422 | 859 | 228 | 11813–12060 | 20000–20937 |
| test | 2,218 | 1,414 | 136 | 12061–12197 | 20938–22437 |

- 三个划分**患者零重叠**（已程序校验），且 ID 连续切分：test 全部是训练时没见过的患者，
  很可能是按时间/批次划分，存在**分布偏移**风险；valid 仅 228 名患者、859 个检查，样本偏小。
- 一次检查含 1–7 张图像（均值 1.64，中位 2）；同一 study 内所有图像的标签集合**完全一致**
  （train 18,513/18,513，valid 859/859），说明标签是 study 级标注传播到每张图，
  有效独立样本量应按 **study 数**而不是图像数估计。
- 无跨划分重复 Dicom_id；图像为 JPG，平均 1.63 MB（最大 7.73 MB）。

## 四、当前模型与进展

- 模型：**torchvision ImageNet DenseNet-121**（非医学预训练，符合比赛第 1 条），10 类 sigmoid 多标签输出，
  384×384 输入，类别加权 BCE，AdamW + 余弦退火，验证集早停/选模。
- 已实现并通过测试：数据加载、患者泄漏校验、macro AUC/F1、训练/评估/推理 CLI、
  官方长表 `submission.csv`（`Study_id, Predict_class, Probability, Gate`）、L1 归一化、
  复赛容器依赖兼容（推理路径不依赖 sklearn）、74 项单元测试 + GitHub Actions 通过。
- **尚未正式训练**：本机无 GPU（torch 2.14.0+cpu），目前只有 8 张图的 CPU 冒烟（指标无意义）。
  因此**当前没有可报告的真实精度**，任何 AUC 数字都要等 GPU 正式训练后才能给出。

## 五、提高精度的路线（按性价比排序）

### 1. 先改验证策略（最重要）
- valid 只有 228 名患者，反复用它调参会过拟合。正确做法：**在 train 内部做患者级 5 折 OOF** 选模型/超参/损失，
  valid 只做最后一次确认。
- 规则允许把 valid 并入训练，但并入后不能再用于早停/选模；建议先冻结方案，再 train+valid 重训最终模型。

### 2. 按 study 组织训练与聚合
- 同一 study 的标签完全一致，可以按 study 采样（一次取该 study 的 1–7 张图），
  用 **多图注意力池化（MIL/Attention）** 代替简单 mean，推理时 study 级聚合。
- 多视图（正位+侧位）联合输入可能明显优于单图独立预测。

### 3. 针对 macro AUC 与稀有类
- macro AUC 只看排序：可用 **pairwise ranking / AUC surrogate loss** 与 BCE 混合，
  而非只优化交叉熵；不依赖阈值选模。
- 稀有类 1–3：class-balanced sampler、focal loss、类别加权；不要只用全量随机采样。
- 类别 10 可做辅助“正常/异常”二分类任务（多任务学习），帮助共享表征。

### 4. 分辨率与增强
- 数据分辨率远高于 384：先用 384 训练，再用 **512 低学习率微调**（progressive resizing）。
- 允许的增强：随机裁剪/旋转/亮度对比度、CLAHE/直方图均衡、Mixup/CutMix；
  推理必须关闭随机增强，保持逐图确定性。

### 5. 模型升级与集成
- 备选（均需非医学 ImageNet 权重、许可证公开可再分发）：ConvNeXt-T、EfficientNet-B0/B3、
  ResNet-50/101、Swin-T。DenseNet-121 是可靠基线（CheXNet 同架构，T4 时延友好）。
- 5 折 × 多种子集成 + TTA（水平翻转、多裁剪）通常能稳定涨点；
  但复赛 **T4 单图端到端 ≤100ms**，集成/高分辨率会逼近上限，需要实测后取舍（必要时知识蒸馏回单模型）。

### 6. 工程与提交细节
- macro AUC 是排序指标，行内 L1 归一化会改变不同 study 间的相对排序，可能轻微影响 AUC；
  上线前在 valid 上对比 `--normalize l1` 与 `none`，若官方示例不要求和为 1，优先 `none`。
- 推理用 FP16（规则允许，需在材料中声明）；`cost.py` 在 T4 上实测 100 图 × 3 轮。
- 测试集不得用于任何训练/统计/选模（规则第 5 条）；增强与 TTA 是允许的，伪标签不行。

## 六、建议的 GPU 执行顺序

1. DenseNet-121 384px 基线：train→valid，拿到真实 macro AUC、每类 AUC、T4 单图时延；
2. train 内 5 折 OOF 调损失/采样/分辨率/聚合方式（这一阶段决定大部分收益）；
3. 选 2–3 个 backbone 做 5 折集成 + TTA，实测时延是否 ≤100ms；
4. 冻结方案 → train+valid 重训 → 生成 submission.csv → 初赛提交；
5. 复赛材料：cost.py、模型卡、许可证、打包。

> 估算：T4 上 DenseNet-121@384 单折 8 轮约 0.7–1.5 小时（取决于 batch 与增强），5 折约 4–8 小时；
> 按 T4 市场价约 1.5–3 元/小时，预算可控。实际耗时需以第一次正式训练为准。
